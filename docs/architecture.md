# Architecture (Draft)

## 목표

운송 요청을 입력받아 여러 운송 모드의 후보를 생성하고, 비용·리드타임·탄소배출·운영 제약을 기준으로 비교 가능한 결과를 제공한다.

## 모듈 경계

- `frontend`: 요청 입력, 후보 경로 비교, 운영 현황 표시
- `backend/app/api`: 외부에 노출되는 HTTP 계약
- `backend/app/domain`: 공통 도메인 모델과 규칙
- `backend/app/agents`: 운송 모드별 후보 생성기
- `backend/app/planning`: 경로 조합, 제약 검증, 점수 계산
- `backend/app/repositories`: 데이터 접근 인터페이스
- `llm-agent`: LLM 기반 추론 실험과 평가

## 초기 원칙

1. API와 에이전트 사이에는 명시적인 스키마를 둔다.
2. 모델 호출이 없어도 핵심 비즈니스 규칙을 테스트할 수 있게 한다.
3. 데이터 소스별 변환 로직은 도메인 로직과 분리한다.
4. 점수 산정 기준과 가중치는 추적 가능하게 관리한다.

## 미결정 사항

- 영속 저장소 및 마이그레이션 방식
- 에이전트 실행의 동기·비동기 경계
- 지도 및 경로 데이터 공급자
- LLM 모델과 장애 시 대체 전략
- 배포 환경과 관측성 도구
