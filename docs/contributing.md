# Contributing

## 작업 흐름

1. 작업 이슈를 만들고 범위와 완료 조건을 적습니다.
2. `feature/<issue>-<summary>` 형식의 브랜치를 만듭니다.
3. 구현과 함께 테스트 또는 수동 검증 방법을 추가합니다.
4. PR에는 변경 이유, 주요 변경점, 검증 결과를 기록합니다.

## 커밋 메시지

커밋은 한 가지 목적만 담고 아래 접두사를 권장합니다.

- `feat`: 기능 추가
- `fix`: 오류 수정
- `docs`: 문서 변경
- `test`: 테스트 추가 또는 수정
- `refactor`: 동작 변경 없는 구조 개선
- `chore`: 설정 및 기타 작업

예: `feat: add shipment request schema`
